# Как именно Роскомнадзор будет фиксировать нарушения по статье 13.55 КоАП

Роскомнадзор будет фиксировать нарушения по **статье 13.55 КоАП** через **автоматизированную систему ботов-сканеров**, аналогичную той, которую ведомство уже запустило в мае 2026 года для проверки персональных данных. Вот конкретный механизм:

### Механизм выявления нарушений по статье 13.55 КоАП

| Этап | Действие Роскомнадзора |
| :-- | :-- |
| **1. Автоматический скрининг** | Специализированный бот **непрерывно сканирует рунет**, имитируя поведение пользователя и выяпля исходный код страниц [^1][^2] |
| **2. Поиск форм авторизации** | Алгоритм осуществляет **поиск форм ввода**, проверяет скрипты аналитики и идентифицирует кнопки «Войти через Google/Gmail/Apple ID» [^1][^3] |
| **3. Сопоставление с реестрами** | Бот **сопоставляет кодовую базу с открытыми реестрами** российских сервисов авторизации (ЕСИА, ЕБС, российские провайдеры) [^1] |
| **4. Логирование нарушения** | Если бот находит хотя бы одно несоответствие (например, кнопку авторизации через Gmail), **сессия логируется, формируется дамп** страницы [^1][^4] |
| **5. Ручная проверка** | Дело передается **сотруднику регионального управления РКН**, который вручную перепроверяет нарушение [^1][^3] |
| **6. Формирование предписания** | При подтверждении нарушения организация получает **предписание об исправлении** (на исправление дают **10 дней**) [^4][^3] |
| **7. Протокол об АП** | По факту выявленного нарушения **составляется протокол об административном правонарушении** [^5] |


***

### Конкретные признаки, которые бот ищет:

| Прибор нарушения | Что бот детектирует |
| :-- | :-- |
| **Кнопки авторизации** | Элементы интерфейса: «Войти через Google», «Войти через Gmail», «Войти через Apple ID», «Войти через Microsoft» [^6] |
| **OAuth-интеграции** | В коде страницы: ссылки на `google.com/oauth`, `appleid.apple.com`, `microsoftonline.com` и другие иностранные сервисы [^1] |
| **JavaScript-скрипты** | Скрипты внешней авторизации: `googleapis.com`, `apple.com/auth`, `github.com/login` [^1] |
| **Интеграции с аналитикой** | Передача данных через **аналитические счетчики без ведома пользователя** ( Яндекс.Метрика, Google Analytics) [^3][^2] |


***

### Ключевые отличия от практики по ПДн:

| Параметр | По статье 13.55 (авторизация) | По статье 13.11 (ПДн) |
| :-- | :-- | :-- |
| **Что проверяет** | Наличие **иностранных способов входа** | Наличие **политики конфиденциальности**, галочек согласия, форм сбора ПД [^3][^7] |
| **Зона охвата** | Все сайты с регистрацией/авторизацией | Сайты, обрабатывающие персональные данные [^3] |
| **Срок исправления** | **10 дней** на исправление [^4] | **10 дней** на исправление [^4] |
| **Массовость** | Точечная проверка, не веерная [^3] | Массовая проверка малого и среднего бизнеса [^3][^4] |


***

### Важное уточнение:

Роскомнадзор **опроверг слухи о массовых предписаниях** и веерной рассылке писем: «паниковать и ждать неминуемого штрафа из-за каждой опечатки на сайте не стоит — реальная практика проверок точечная, а не тотальная».[^3]

Таким образом, **нарушения будут выявляться преимущественно автоматически ботом**, а затем проверяться вручную инспектором РКН перед вынесением штрафа.
