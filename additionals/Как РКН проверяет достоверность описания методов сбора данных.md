# Как РКН проверяет достоверность описания методов сбора данных

РКН проверяет достоверность описания методов сбора данных через **сравнительное сопоставление** заявленных в документах процессов с **фактическими техническими реализациями** на сайте. Механизм проверки включает несколько этапов:

***

## Этапы проверки достоверности описания методов сбора данных

### 1. Автоматический скрининг сайта ботом

| Что проверяет бот | Как проверяет |
| :-- | :-- |
| **Наличие JavaScript-скриптов** (Google Analytics, Яндекс.Метрика, Facebook Pixel) | Бот анализирует код страницы, ищет ссылки на `google-analytics.com`, `yandex.ru/metrika`, `facebook.com/tr` [^10][^11] |
| **Использование cookie-файлов** | Бот проверяет, создаются ли cookie-файлы при первом посещении, анализирует их содержимое [^10][^12] |
| **Передача данных в аналитические сервисы** | Бот фиксирует HTTP-запросы, отправляемые на внешние сервера (например, `api-metrics.com`, `analytics.google.com`) [^10] |
| **Сбор данных через формы** | Бот проверяет, какие поля есть в формах (email, телефон, имя), и фиксирует отправку данных [^12][^13] |


***

### 2. Сопоставление с документами компании

| Документ | Что сопоставляет инспектор |
| :-- | :-- |
| **Политика конфиденциальности** | Сравнивает фактические методы сбора (собранные ботом) с описанными в политике [^1][^5] |
| **Уведомление о начале обработки ПДн** | Проверяет, совпадают ли заяванные в уведомлении процессы с фактическими [^5][^7] |
| **Правила применения рекомендательных технологий** | Сравнивает заявленные методы анализа предпочтений с фактическими алгоритмами [^14][^15] |
| **Формы согласия пользователей** | Проверяет, соответствуют ли пункты согласия фактическим методам сбора данных [^1][^5] |


***

### 3. Проверка на соответствие индикаторам риска

РКН выявляет **индикаторы риска**, которые автоматически запускают внеплановую проверку:[^7]


| Индикатор риска | Пример несоответствия |
| :-- | :-- |
| **Заявили «не собираем ПДн», но есть форма с email** | В политике написано *«не обрабатываем персональные данные»*, но на сайте есть форма подписки на email [^1] |
| **Описали только cookie, но есть Яндекс.Метрика** | В правилах указано *«собираем только cookie-файлы»*, но бот обнаружил скрипт `yandex.ru/metrika` [^10][^11] |
| **Технически передали данные в Facebook Pixel, но не описали** | В документе не указано *«передаем данные в Facebook»*, но код страницы содержит `facebook.com/tr` [^10] |
| **Заявили, что данные хранятся в РФ, но IP-адрес сервера — в ЕС** | В политике написано *«данные хранятся в России»*, но бот заметил, что запросы идут на сервер `amazonaws.com` (ЕС) [^11] |


***

### 4. Инспекторская проверка (при наличии индикаторов риска)

| Что делает инспектор | Как проверяет |
| :-- | :-- |
| **Личный визит в организацию** | Инспектор приезжает в офис, получает доступ к IT-системам, анализирует серверные логи, базы данных [^3][^4] |
| **Запрос технической документации** | Требует предоставить документацию по IT-системам: схемы передачи данных, архитектуру баз данных, настройки CRM [^5][^6] |
| **Сравнение с реальными процессами** | Проверяет, как фактически происходят процессы: какие данные собираются, где хранятся, кому передаются [^4][^6] |
| **Тестирование форм сбора** | Побывает как пользователь, заполняет формы, проверяет, какие данные реально отправляются [^5] |


***

## Примеры несоответствий, которые выявляет РКН:

### Пример 1: Несоответствие в методах сбора

| Что написано в документе | Что на самом деле |
| :-- | :-- |
| *«Собираем только cookie-файлы и историю просмотров»* | Бот обнаружил: Google Analytics, Яндекс.Метрика, Facebook Pixel, передачу email в CRM [^10] |
| **Результат проверки** | Нарушение выявлено → штраф до 700 тыс. руб. для юрлица (ст. 13.56 КоАП) [^16] |

### Пример 2: Несоответствие в источниках данных

| Что написано в документе | Что на самом деле |
| :-- | :-- |
| *«Данные получаются только через сайт»* | Бот заметил: данные поступают из Facebook, Google, Instagram через интеграции API [^10] |
| **Результат проверки** | Нарушение выявлено → штраф до 700 тыс. руб. для юрлица [^16] |

### Пример 3: Несоответствие в локализации данных

| Что написано в документе | Что на самом деле |
| :-- | :-- |
| *«Данные хранятся на серверах в России»* | Бот заметил: IP-адрес сервера — `104.21.12.34` (AWS, США), запросы идут на сервер в ЕС [^11] |
| **Результат проверки** | Нарушение по ст. 13.14 КоАП → штраф для юрлица 300–700 тыс. руб. [^17] |


***

## Ключевой принцип проверки:

**РКН проверяет не только наличие документов, но и корректность выбранных правовых оснований** — то есть, насколько фактическая реализация процессов соответствует заявленным в документах описаниям.[^5]

Если бот выявляет **даже один индикатор риска** → РКН проводит **внеплановую проверку** с личным визитом инспектора.[^7]
