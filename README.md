# double_sitechecker — аудит сайтов (152-ФЗ · санкции · авторизация)

Веб-приложение для автоматизированной проверки сайтов на соответствие
российскому регулированию:

| Модуль | URL | Назначение |
|--------|-----|------------|
| **152-ФЗ** | `/` | Политика ПД, cookie, формы, согласие, трекеры, риск/штрафы |
| **Санкции** | `/sanctions` | Meta, заблокированные сервисы, CDN, платежи и др. |
| **Авторизация** | `/auth` | РФ-сервисы входа vs иностранный OAuth, 152-ФЗ при регистрации |
| **История** | `/history` | Архив аудитов с выгрузкой отчётов |
| **Админка** | `/admin` | Тема, лимиты, AI-модель, брендинг |

**Стек:** Python 3.10+ · Flask · BeautifulSoup · Playwright · OpenAI-совместимый API · python-docx  
**Десктоп (Windows):** pywebview + PyInstaller + Inno Setup · данные в `%APPDATA%\Sitechecker`

**Скачать Windows:** [Releases](https://github.com/neuromafka-create/Sitechecker/releases) — `Sitechecker-Setup-x.y.z.exe`

## Возможности

### 152-ФЗ (`/` · `checker.py`)
- Политика обработки ПД (11 обязательных разделов ст.14 152-ФЗ), футер, PDF
- Cookie-баннер, кнопка отказа, предустановленные галочки
- Аналитика: Яндекс.Метрика (РФ), Google Analytics / Meta Pixel / Hotjar и др. (иностранные = трансграничка)
- Иностранные ресурсы: Google Fonts, reCAPTCHA, CDN и т.п.
- Формы сбора ПД (в т.ч. JS-формы без `<form>`), согласие по ст.9
- Многостраничный обход (до 5 страниц на домен)
- Playwright: трекеры до согласия, скрытые баннеры, `element.checked`, скриншоты
- AI-рекомендации и ТЗ разработчику (.docx, SSE-стриминг)
- Оценка риска и ориентиры по штрафам КоАП РФ

### Санкции (`/sanctions` · `sanctions/`)
- База ~24 ресурсов в 8 категориях (Meta, banned, payment, CDN, ads, widgets…)
- Краулинг страниц, уровни риска, Excel-экспорт, AI-рекомендации
- Фильтрация ложных срабатываний на JS-шаблонах Tilda (соцсети «на будущее»)

### Авторизация (`/auth` · `auth/`)
- Разрешённые: Госуслуги/ЕСИА, Сбер ID, Яндекс ID, VK ID и др.
- Иностранный OAuth: Google, Facebook, Apple, Telegram Login и др.
- Согласия, CAPTCHA, возраст, MFA — по сигнатурам в HTML

### История и админка
- Сохранение результатов аудитов в SQLite (`history.db`) по разделам
- Скачивание Excel/CSV (в т.ч. пересборка из сохранённых данных)
- Удаление отдельных записей
- Настройки: тема, логотип, max URL / страниц, AI-модель

## Быстрый старт

```bash
# 1. Каталог проекта
cd double_sitechecker

# 2. Виртуальное окружение
python -m venv venv

# Windows
.\venv\Scripts\activate
# Linux / macOS
source venv/bin/activate

# 3. Зависимости
pip install -r requirements.txt

# 4. Playwright (для углублённой проверки 152-ФЗ)
# Windows:
python -m playwright install chromium
# Linux (часто):
# PLAYWRIGHT_BROWSERS_PATH=0 python -m playwright install chromium

# 5. Переменные окружения (.env)
#    HUBRIS_API_KEY / HUBRIS_BASE_URL / HUBRIS_MODEL — AI (опционально)
#    ADMIN_PASSWORD — пароль админки
#    PORT — порт (по умолчанию 6001)

# 6. Запуск
python app.py
```

Открыть в браузере: **http://127.0.0.1:6001**  
(порт `6001` — Chrome блокирует 6000 как unsafe; переопределение: `PORT=8080 python app.py`)

История и админка: `/history`, `/admin` (нужен `ADMIN_PASSWORD`).

## Критерии 152-ФЗ

| № | Критерий | Что проверяется |
|---|----------|-----------------|
| 1 | Политика ПД | Ссылка (в т.ч. `/politika-pd/`), футер, 11 разделов ст.14, реквизиты оператора, PDF |
| 2 | Cookie и метрика | Баннер, отказ, галочки, аналитика, иностранные ресурсы |
| 3 | Формы с ПД | phone/email/имя, JS-формы, дедупликация между страницами |
| 4 | Согласие | Чекбокс, реквизиты ст.9, `element.checked`, совмещение с рассылкой |
| — | Playwright | Трекеры до согласия, скрытый баннер, скриншот, JS-формы |

### Аналитика vs трансграничка

| Системы | Аналитика | Трансграничная передача |
|---------|-----------|-------------------------|
| Яндекс.Метрика, LiveInternet, Roistat | да | **нет** |
| Google Analytics, Meta Pixel, Hotjar, SimilarWeb | да | **да** |
| Google Fonts, reCAPTCHA, CDN… | — | **да** |

Сигнатуры GA не используют голый `dataLayer` (на Tilda это stub без GA).

## Многостраничная проверка

До **N страниц** на домен (админка / `max_pages`):

1. Полная проверка стартовой (с Playwright при включении).
2. Краулинг внутренних ссылок (приоритет: контакты, услуги, заявка…).
3. Доп. страницы — аналитика, формы, согласие.
4. Слияние: лучшая политика, union аналитики/foreign, дедуп форм, max риск.

Пропускаются: login/register, cart, admin, sitemap, pdf, `tel:`, `mailto:`, якоря.

## Оценка риска (152-ФЗ)

Реализовано в `checker.py` → `assess_risk()`. Это **эвристическая балльная модель** для приоритизации аудита, а не расчёт штрафа для протокола РКН. Цифры ориентированы на порядки ст. 13.11 КоАП РФ, но **не заменяют** юридическую оценку.

### Формула

```
penalty     — сумма штрафных баллов за нарушения
protection  — сумма защитных баллов за выполненные требования
discount    = min(protection, 40% от penalty)   # защита режет максимум 40% штрафов
score       = max(0, penalty − discount)
```

Многостраничная проверка: по каждой странице свой `assess_risk`; **итоговый риск сайта = наихудший** среди страниц (КРИТИЧЕСКИЙ > ВЫСОКИЙ > СРЕДНИЙ > НИЗКИЙ); список нарушений — объединение с дедупликацией.

### Уровни риска по итоговому score

| Уровень | Условие | Смысл (ориентир) |
|---------|---------|------------------|
| 🔴 **КРИТИЧЕСКИЙ** | `score ≥ 700 000` | Тяжёлые составы: трансграничка без контроля cookie и/или трекеры до согласия + несколько крупных дыр |
| 🔴 **ВЫСОКИЙ** | `220 000 ≤ score < 700 000` | Существенные нарушения cookie/трансгранички или сочетание средних |
| 🟡 **СРЕДНИЙ** | `100 000 ≤ score < 220 000` | Частичные нарушения политики, форм, cookie |
| 🟢 **НИЗКИЙ** | `score < 100 000` | Нет крупных штрафов или они сильно смягчены защитой |

**Граница КРИТИЧЕСКИЙ / ВЫСОКИЙ — 700 000 баллов.**  
**Граница ВЫСОКИЙ / СРЕДНИЙ — 220 000.**  
**Граница СРЕДНИЙ / НИЗКИЙ — 100 000.**

### Штрафные баллы (`penalty`)

| Условие | Баллы | Примечание в UI / ориентир ₽ |
|---------|------:|------------------------------|
| Трекеры грузятся **до** согласия, среди них есть **иностранные** | **+500 000** | до 500 000 ₽ |
| Трекеры до согласия, **только российские** (напр. Метрика) | **+300 000** | cookie, не «за рубеж»; до 300 000 ₽ |
| **Иностранные ресурсы** (GA, Meta, Hotjar, Google Fonts, CDN…) **и** нет cookie-баннера | **+500 000** | максимум по трансграничке |
| Иностранные ресурсы **и** баннер есть, **нет** кнопки отказа | **+375 000** | |
| Иностранные ресурсы **и** баннер + кнопка отказа | **+250 000** | смягчение: пользователь мог отказаться |
| Нет cookie-баннера **при наличии** любых трекеров | **+300 000** | до 300 000 ₽ |
| Баннер есть, но **нет** кнопки «Отказаться» | **+200 000** | до 300 000 ₽ (не полный максимум) |
| Галочка согласия **предустановлена** | **+300 000** | до 300 000 ₽ |
| Playwright: баннер в HTML есть, но **не виден** при первом заходе | **+200 000** | до 300 000 ₽ |
| Политика обработки ПД **не найдена** | **+150 000** | до 150 000 ₽ |
| В политике **не хватает разделов** (из 11 по ст. 14) | **+12 000 × N**, max **+100 000** | N = число отсутствующих; до 150 000 ₽ |
| Ссылка на политику **не в футере** | **+50 000** | |
| Политика только **PDF** (риск для АС МПДн) | **+30 000** | без отдельного cap ₽ в тексте |
| **Реквизиты оператора** не найдены в политике | **+50 000** | |
| Есть формы с ПД **без** чекбокса согласия | **+100 000** | до 100 000 ₽ |
| Каждое нарушение **реквизитов согласия** (ст. 9) | **+60 000** | суммируется по каждому пункту; до 100 000 ₽ в тексте |

Российская аналитика (Яндекс.Метрика и др. из `RUSSIAN_ANALYTICS`) **не** попадает в блок «иностранные ресурсы»; иностранная аналитика и CDN — попадает.

### Защитные баллы (`protection`)

| Условие | Баллы |
|---------|------:|
| Только отечественные трекеры (нет foreign) | **+100 000** |
| Cookie-баннер найден | **+150 000** |
| Есть кнопка отказа | **+100 000** |
| Политика ПД найдена | **+75 000** |
| Все 11 разделов политики на месте | **+75 000** |
| Ссылка на политику в футере | **+25 000** |
| Реквизиты оператора найдены | **+25 000** |
| Формы с ПД есть и с чекбоксом согласия | **+50 000** |

Скидка: `discount = min(protection, floor(penalty × 0.4))` — даже идеальный баннер/политика **не обнуляют** тяжёлую трансграничку, но могут перевести score через границу уровня.

### Примеры (грубо, до округления)

| Сценарий | penalty (≈) | protection (≈) | score (≈) | Уровень |
|----------|------------:|---------------:|----------:|---------|
| Только Яндекс.Метрика, баннер + отказ, политика полная | 0 | высокий | **0** | 🟢 НИЗКИЙ |
| GA + баннер + отказ, без прочих дыр | 250 000 | ≥100 000 | **~150 000** | 🟡 СРЕДНИЙ |
| GA **без** баннера | 500 000 | мало | **≥300 000** | 🔴 ВЫСОКИЙ |
| Иностранные трекеры **до** согласия + foreign без баннера | 500 000 + 500 000 | cap 40% | **≥600 000**, часто **≥700 000** | 🔴 ВЫСОКИЙ / **КРИТИЧЕСКИЙ** |

### Санкции и авторизация (другие правила)

В модулях **Санкции** и **Авторизация** нет score 700 000. Риск = **наивысший severity** найденных сигнатур (`critical` > `high` > `medium` > `low` > `clean`).  
В **Авторизации** на итоговый риск влияют только категории `auth_foreign` и `rec_tech` (ЕСИА/Сбер и security-info уровень не поднимают).

## Отчёты и AI

- **Excel / CSV** — сводка и детализация; из UI и из истории
- **DOCX** — рекомендации владельцу и/или ТЗ разработчику (после AI-генерации)

Пример `.env` для AI:

```env
HUBRIS_API_KEY=sk-...
HUBRIS_BASE_URL=https://api.hubris.pw/v1
HUBRIS_MODEL=qwen/qwen3.5-flash-02-23
# Лимит длины ответа (по умолчанию 16384):
# AI_MAX_TOKENS=16384
ADMIN_PASSWORD=change-me-in-production
PORT=6001
```

Без API-ключа проверки работают, блок AI-рекомендаций — нет.  
Модель также можно задать в админке (вкладка «AI модель»).
